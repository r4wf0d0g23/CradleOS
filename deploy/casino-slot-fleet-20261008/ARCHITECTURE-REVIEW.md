## Integration / persistence requirements

1. **One authoritative commit.** Check aggregate stake against current balance before drawing; generate the whole bounded tape; debit once and credit its final capped return once in the same v2 write. If generation/validation/storage fails, no balance/history/UI outcome changes. Free/cascade/hold stages never debit again. A reveal action changes only the cursor; immutable receipt, balance, sequence, history and stake remain byte-equivalent otherwise.
2. **Do not reuse stale cursor callbacks.** Next/auto-next/Reveal all must read the latest current ref, check the expected immutable round identity and pending status, and persist before rendering. Old timer completion after skip→new spin, refill, mode switch or unmount must not overwrite a newer round or regress its cursor. Cursor is monotonic0..frameCount, with explicitly documented meaning; repeated completion does nothing. Reload/replay reads only recorded entropy, never fresh crypto.
3. **Correct pending route and locks.** Existing initialization is `activeSession ? blackjack : pack.game`; pending slot sessions need their actual fleet key. New spin/game/mode/donation/refill and keyboard paths all use the same pending predicate. Keep an accessible Reveal all, including while paused/hidden/reduced motion or an animation errors, so presentation cannot trap credited funds or force watching28steps. Full app navigation may unmount; exact pending receipt resumes on return.
4. **Migration stays absent-only.** Extend old v2 with an absent-field default only when no slot-era fields are present; malformed slot payload/version/cursor cannot be silently discarded or revived from stale v1. Reject simultaneous active legacy hand/new blackjack table/pending slot. Preserve old25-game packs/history/hands. Update canonical game registries/validators/catalog consciously:33 practice total, still23 staged testnet; no fabricated chain module entries or default fallthrough builder.
5. **Freeze replay version before launch.** Parent confirms version1 economic rules will freeze after calibration, fingerprinted by regression. Future odds/weights/scale/feature changes require an explicit new rules version with old replay retained. Exact current replay also compares generated `frame.label` strings: even future copy-only edits can invalidate old receipts unless labels derive from stable codes or old version strings are retained. A receipt-supplied scale/paytable is not authority.
6. **Bound serialized shape, not just entropy.** Current32frame/4000draw caps are adequate, but enforce raw-save byte length and per-grid column/row/win/cell/coin limits before deep stringify where practical. Validate game/version/stake/cursor, exact consumed draw count, integer bounds and all economic intermediate products. No supplied grid, total, cap flag, coin value or free-spin count bypasses replay. Persist only newest full tape, not full tape copies in every history row.
7. **Progressive balance display is cosmetic.** Ledger is final immediately. Display can mask unrevealed payout via final balance minus remaining committed award, never a second escrow/debit. History/result UI must not reinterpret a completed slot under current controls. A revealed sub-stage return is not proof the whole paid spin won; net-loss/equal-return rounds must not receive a profit celebration.

## Mechanics that must be explicit

- Whole-spin price, not per-line; these weighted independent cells are not physical reel strips. State lowest matching length, leftmost consecutive reel rule and highest single award per payline; wild substitution does not multiply-pay the same line. Ways presently have no wild symbols (zero wild weight), so don't imply wild substitution there.
- Base-only scatter triggers, fixed awarded free count, **no retriggers**. Declare whether Drone sticky wilds begin only on free spins (current implementation) or carry from the triggering base; do not silently show base wilds locking if they do not.
- Gatecrash trigger count uses original pre-expansion symbols; payout uses expanded grid. Preserve both for display/replay. Free multipliers already apply to win points; renderer must not multiply a second time.
- Reactor counts anywhere; Feral counts orthogonally connected components, not diagonals or row-wrapping neighbors. Cascade removal is union of winning cells, survivors fall preserving column order, refill only vacated cells. Stage6/4 is a declared terminal paid stage, not an unshown extra cascade.
- Vault: fewer than6initial coins pays zero;6+ triggers. Three **misses**, reset to3 on any new locked coin. Lock cells/values once; only newly empty positions draw. Collected coins pay once at the end. Call the full-grid extra a **fixed full-grid bonus**, not a fixed total/top payout: collected values vary, and a rare large coin can exceed a low-valued full grid. Clearly distinguish coin points from actual stake multipliers after scale/cap.
- Current cash awards use **cumulative rounding**: `award_i = floor(stake*cumulativePoints*scale/1e8) - previousTotal`, capped at2500×. This may differ by a cent from summing independently floored frame/line returns. Publish the convention and derive on-screen stage amounts from saved awards. Distinguish “cap reached” from “positive cap adjustment” when equality lands exactly at the cap; current `capReached` means uncapped integer return is strictly greater.

## Math / validation acceptance

- Freeze calibration coefficients using calibration seeds, then evaluate independent held-out seed families. If coefficients change, validate anew; do not cherry-pick the evaluation mean. Simulate complete **paid spins including all free stages**, cap and integer rounding at1,25,1000chip stakes. Use unbiased bounded draws in production and simulation.
- Report observed return, positive-return rate, **net-profit** rate separately, bonus rate, stage-count distribution, full-grid frequency, cap-adjustment rate and sample count. Report uncertainty method honestly; heavy tails/cap events require multiple batches/seeds, variance, maxima/tail counts and ideally independent exact/DP anchors. A tight normal CI from too few rare payouts is not certification. Zero observed cap/jackpot events does not prove impossibility; report a one-sided event-rate bound rather than0% certainty.
